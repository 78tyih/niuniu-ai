• ## 二、技术方案与权限

  **1. 结论：不改变，仍选方案 B，但这只代表技术与运维上更可取，不代表号池业务合规。**  
  理由：Access Token 消除了 fork、模拟登录、保存密码和长期 Cookie 等问题，但没有解决 Admin 权限过大、额度来源、转售授权、备案和数据流向问题。  
  具体做法：把 B 限定为“服务端自动开户、发 key、调额”的实现方案；技术验证与商业上线分别设闸门。可以使用测试额度验证流程，但不能因为接口跑通就直接采购灰色额度或向客户收费。

  **2. 结论：下游每客户独立凭证必须有；上游每客户 token 按需使用；上游每客户子账户在最小版本中仍不必要。**  
  理由：如果所有请求都经过你的服务端，上游是否每客户一个 token，并不会显著改善客户端被盗后的隔离，你的下游账户、额度和风控才是主控制面。过多上游账户还会增加对账、密钥保管和生命周期管理成本，也不产生法律隔离。  
  具体做法：
  - 默认采用少量上游生产子账户和服务级令牌，在自己网关内为每客户建立独立 key、余额、速率限制和封禁状态。
  - 只有需要独立上游硬额度、单独结算或单独停用的企业客户，才启用每客户上游 token／子账户。
  - 不建议 Windows 客户端直连上游；若坚持直连，则每客户独立、可撤销的上游凭证就成为必需品，但仍不如服务端代理安全。

  **3. 结论：不要直接接收一把仅靠口头承诺“受限”的 Admin 令牌；优先让 Admin 令牌留在伙伴环境，由伙伴侧最小化代理执行白名单操作。**  
  理由：Public／User／Admin／Root 是角色分级，不天然等于接口级、对象级权限控制。裸 Admin 令牌仍可能修改任意用户额度；来源 IP 限制也必须确认是实际配置并测试通过的能力，不能当作默认存在。  
  具体做法：
  - **能做：**仅在指定账户池内创建普通用户、创建普通令牌、为指定订单调整额度。
  - **不能做：**创建或修改 Admin／Root，操作其他客户，修改价格、分组、渠道和模型配置，访问财务、兑换、日志或全量用户数据。
  - **防滥用：**代理校验账户 ID 白名单、订单号和幂等键；设置单笔、单日、单月调额上限，累计发放额度不得超过已确认采购额度；超额操作双人复核。
  - 使用固定出口 IP、网络白名单或 mTLS，令牌定期轮换并验证即时撤销；完整 key 不进入日志、客户端或工单。
  - 保存带操作者、客户、订单、调整前后额度的追加式审计账；定期用越权请求做负向测试，确认不能跨客户调额或调用非白名单接口。

  ## 三、合规风险

  **1. 结论：灰色号池属于高风险上游；“我不知道”不是通用抗辩，但 Token 分销本身也不能一概等同犯罪。**  
  理由：
  - 行政上，你可能因自己面向境内公众提供服务的备案、内容安全或数据处理问题被直接追责，并不只是替上游承担连带责任。
  - 民事与经营上，上游违反厂商条款、封号或额度消失，仍可能导致你对客户退款、违约和赔偿。
  - 刑事上，具体责任取决于账号取得、支付来源、退款操作及你的参与程度；报道中的刑拘不是有罪判决。但异常低价、批量账号、借证认证、拒绝提供来源等红旗，可能成为认定明知或应知的间接证据。刻意“不问来源”尤其危险。
  - 另有个人信息的处理与出境、商业秘密泄露、无合法成本凭证、税务及停服风险。

  具体做法：来源未核验前不采购、不大额预付、不转售；保存尽调、合同、发票和沟通记录；绘制真实的账号、资金、请求和数据流向图；预先准备上游失效时的停服、客户通知和退款方案。

  **2. 结论：文件可以证明合理尽调并改善追偿能力，但不能把行政、刑事或你自己对客户的责任完全“隔离”。**  
  理由：监管看实际服务和数据流，不只看合同；赔偿条款通常只在合同双方之间有效。  
  具体做法：至少索取并独立核验以下材料：
  - 签约主体营业执照、实际受益和结算主体，以及按业务形态适用的许可、备案或登记材料。
  - 模型厂商或一级授权商的采购合同、合法发票、转售／分销授权，明确是否允许向你批发、是否允许你用于境内公众付费服务。
  - 书面保证不存在批量薅免费额度、借用身份、盗号盗刷、未授权订阅拆分、骗退款及规避地区限制。
  - 实际模型、端点、所有分包商及数据流向清单；签署数据处理条款，约定保存期限、是否用于训练、删除、出境和安全事件通知。
  - 审计权、来源追溯、上游变化提前通知、立即停用与退出、退款及损失赔偿条款。
  - 保持合同、付款、发票和实际服务一致；定期向模型厂商或官方渠道复核，而不是只收截图。

  **3. 结论：备案责任按实际服务提供者和上线形态判断，不能自动推给伙伴或模型厂商；你以自己品牌面向境内公众提供功能时，必须单独判断自己的备案或登记义务，但不等于一律重新做“模型备案”。**  
  理由：模型厂商的备案主要覆盖其模型和对应服务，不当然覆盖你的独立应用、域名或聚合服务。直接调用已备案模型的应用，在部分实践口径中可能走登记；自行聚合、路由、增强或独立提供服务的，义务可能不同。具有舆论属性或社会动员能力时，还可能涉及安全评估、算法备案等其他要求。收费、邀请制或仅 Windows 客户端并不当然排除“面向公众”。  
  具体做法：上线前让熟悉生成式 AI 监管的中国律师，按“客户看到谁的服务、谁决定模型和输出、请求经过谁、数据存在哪里”逐项认定角色，并向属地网信部门确认应走备案、登记还是其他程序；留存咨询和办理记录，不宣传“上游已备案，所以我们无需办理”。

  **4. 结论：可以降到相对可接受，但必须同时满足来源真实、转售有权、自身手续完成和数据路径可控，不能只凭“国内知名品牌”放行。**  
  理由：备案不解决转售授权、个人信息、内容安全、消费者退款和税务问题；聚合商还可能暗中切换模型或跨境转发。  
  具体做法：逐一核验具体服务和模型的备案状态，不只核验品牌；优先直接签官方 API，伙伴模式则核验完整授权链；在网关设置模型与境内端点白名单，禁止未经批准的自动 failover；逐请求记录实际模型和上游；落实内容安全、投诉处理、隐私政策、数据删除及安全事件流程。满足这些条件后再小范围上线。

  **5. 结论：下列形态应直接拒绝或冻结准入，价格不能抵消风险。**  
  理由：这些形态的核心问题是来源、授权或数据不可证，部分还包含明显欺诈或规避行为，你可能直接参与并承接停服和刑事调查风险。  
  具体做法：红线包括：
  - 批量注册境外账号、购买或借用他人身份认证，或无法解释账号真实来源。
  - 未获厂商明确授权，将个人／团队包月订阅、网页 Session、Cookie 或免费试用额度拆成 API 转售。
  - 盗号、盗刷、虚假支付、故意触发封号骗退款，或教你规避地区、风控和封禁。
  - 拒绝披露签约主体、实际上游、模型及数据流向，或者无法提供可核验授权链和合法结算凭证。
  - 名义上是境内备案模型，实际隐性路由至境外或未核验服务，或者擅自保存、出售、训练客户内容。
  - 要求你在适用的备案、登记或其他法定程序未完成前，向境内公众开放。

  尽调话术可直接说：  
  **“这是我们统一的供应商准入和审计要求，麻烦您提供额度来源与转售授权、实际模型及数据流向、适用备案登记和开票材料，材料齐全我们才能长期合作并扩大采购。”**

  ## 四、最小可上线路径

  **结论：最小风险路径不是先接号池再补合规，而是“一个境内已备案模型的官方或明确授权 API＋自己的服务端网关＋有限客户收费上线”。**  
  理由：先减少上游层级、模型数量和密钥分权，才能同时缩小技术、数据和合规审计范围。  
  具体做法：
  1. 选一个具体模型和境内官方端点，核验其备案状态、服务条款及是否允许你的使用方式；先用合成数据做内部技术验证。
  2. 确认你自身需要办理的备案、登记、安全评估或其他手续，并完成合同、隐私政策、内容安全和投诉流程。
  3. 客户端只连接你的网关；网关保管上游密钥，提供下游每客户 key、额度、限流、审计、模型白名单和总停用开关。初期不做每客户上游子账户。
  4. 确需伙伴自动开户时，再接入前述受限代理；不为省事把裸 Admin 令牌放进客户端或普通业务服务器。
  5. 先小额、短周期销售并保留退款和停服能力，验证账单、额度与上游消耗一致后再扩大。

  **硬性闸门：没有中国律师对服务角色、授权链、备案登记和数据路径的意见，不应对境内公众正式开放；没有会计或税务专业人士确认合同、收入确认、退款和发票口径，不应收费上线或做大额不可退预付采购。内部合成数据测试可以先做。**

  ## 其他人可能漏掉的重叠点和风险

  - **“可撤销、可审计”不等于“低权限”：**裸 Admin 令牌即使能撤销，在撤销前仍可能造成高额损失；审计日志只能帮助追责，不能替代前置限额。
  - **调额不是普通配置，而是在发放具有经济价值的使用额度：**必须将客户订单、实际付款、上游采购和 New API 额度流水四方对账，不能只依赖后台一条“管理员修改额度”日志。
  - **技术自动化可能放大合规证据和风险：**批量开户、批量发 key 既提高效率，也放大滥用规模；它不能证明额度合法，反而要求更严格的供应商准入。
  - **备案对象可能错配：**同一模型已备案，不代表你的品牌、应用、域名、聚合服务或新增功能已覆盖；伙伴的备案也不当然覆盖你。
  - **“境内模型”不等于“境内数据路径”：**聚合商仍可能跨境转发、使用境外可观测平台或把提示词交给未知分包商，必须核验实际端点和遥测链路。
  - **官方 API 的使用权不等于原始 Token 转售权：**在自己软件中提供 AI 功能，与把上游 key 或额度原样分销，可能是不同授权事项。
  - **刑拘报道既不能推出“所有分销都违法”，也不能反向当作安全证明：**应依据具体来源、授权、主观明知和参与行为判断，避免把个案标题当成法律规则。
  - **合同隔离有边界：** indemnity／赔偿条款只能改善事后追偿，不能阻止监管处罚、刑事调查或客户向你索赔。
