## 任务 A：策略广场的卡片字段设计

以下是面向牛牛 AI 的设计建议，不代表对 AlphaFox 或 OTFAX／OTFX 现有界面的实测结论。整体原则是：**收益负责吸引注意，风险必须同时可见，曲线帮助用户判断收益过程。**

### 1. 卡片字段层级

建议使用**单列、接近全屏宽度的卡片**，每张只展示一个策略。移动端双列会挤压曲线和风险指标，不利于比较。

推荐结构：

```text
[头像] 黄金趋势策略                   [收藏]
       策略方名称 · 实盘 · 运行 286 天

年化收益率                         最大回撤
+28.64%                            12.80%
[近一年 ▾]                         统计区间内

[             净值曲线                   ]

夏普比率 1.42             交易笔数 386

128 人正在跟随                    [跟单]
```

这里的数值仅用于示意。字段层级建议如下：

| 层级 | 字段 | 排版建议 |
|---|---|---|
| **一级：收益与风险** | 年化收益率、最大回撤 | 年化数字 `30–34px / 600`；最大回撤 `20–24px / 600`，与收益同排，不能缩进角落 |
| **二级：走势与质量** | 净值曲线、夏普比率、交易笔数 | 曲线独占一行；夏普、交易笔数数字 `16–18px / 500`，标签 `12–13px` |
| **三级：身份与背景** | 策略名、策略方、运行天数、当前实盘跟随人数、实盘／模拟标识 | 策略名 `17–18px / 600`；辅助信息 `12–13px`、中性灰 |

补充规则：

- **策略名是识别入口**，字号可以大于普通指标，但不要抢过收益数字。
- 最大回撤展示为正的幅度，例如 `12.80%`，由标签说明含义；不要与亏损收益率的负号混用。
- 图标只辅助识别，例如收藏、实盘验证、指标说明；**不要用图标代替“夏普比率”等标签**。
- 跟随人数明确标注“当前正在跟随”，避免把累计人数当作当前活跃人数。
- 列表统一统计区间，例如“近一年”；不足一年时标注实际天数。样本太短时展示“年化数据不足”，不能让几天收益外推出来的大数字成为主视觉。
- 年化、夏普、最大回撤的统计口径应一致，并可查看说明。

### 2. 曲线展示

**推荐：以净值为基础的迷你折线图，搭配很浅的面积填充。**

- 高度 `56–72px`，左右与卡片指标对齐。
- 折线宽度 `1.5–2px`；填充透明度约 `6%–10%`。
- 小卡片隐藏密集坐标轴、网格和数据点，只保留起止时间或明确的区间标签。
- 使用包含浮动盈亏的净值数据，并剔除入金、出金对收益表现的影响；不要把充值造成的余额增长画成策略收益。
- 不做过度曲线平滑，避免掩盖真实回撤。
- 无数据展示占位说明，不能画成收益为零的直线。

**基准线：默认不加市场基准对比虚线。**

- 外汇、黄金、多资产策略未必有适用的统一市场基准。
- 可加一条轻灰色的**起始净值线**，明确其代表起点，而非业绩基准。
- 详情页再按需提供基准对比，并说明选取理由和计算口径。

**中国市场颜色约定：**

- 正收益：红色，如 `#D92D20`。
- 负收益：绿色，如 `#15803D`。
- 零收益：中性灰。
- 橙色 `#FF6A1A` 专用于品牌和操作，不承担涨跌含义。
- 整条小曲线按所展示区间的累计收益正负着色，不必每段红绿交替；涨跌仍通过曲线方向表达。
- 最大回撤用中性深色；只有触发明确的风险阈值才加风险提示，避免把所有风险数据都涂红。

还要避免一个误导：**各卡片如果自动缩放纵轴，走势可以看，波动大小不能直接横向比较。**进入“对比”模式后，应统一时间与纵轴尺度。

### 3. 卡片操作

建议每张卡片保持 **一个主操作、一个轻操作、一个详情入口**。

- **跟单：右下角主按钮**
  - 橙色实底，触控区域至少 `44 × 44pt`。
  - 文案直接用“跟单”。
  - 已跟随后显示“管理跟单”，同时附上“跟随中”状态。
- **查看详情：点击卡片主体**
  - 策略标题、指标区、曲线区均可进入详情。
  - 收藏、跟单等按钮独立响应，避免误触进入详情。
  - 可在标题附近放小箭头提示可进入。
- **收藏：右上角**
  - 使用线性星标或书签。
  - 图标可以只有 `20–24pt`，但热区仍至少 `44pt`。
- **对比：放在列表工具栏**
  - 点击“对比”后，卡片出现选择框，底部显示“对比已选策略”。
  - 移动端建议每次比较 `2–3` 个策略，避免每张卡片常驻多个操作按钮。

不建议把分享、举报、策略方主页等操作都铺在卡片上，放到详情页更合适。

### 4. 列表／详情分工

**列表页解决“哪些值得进一步看”，详情页解决“为什么值得跟、会承担什么风险”。**

| 内容 | 列表页卡片 | 详情页 |
|---|---|---|
| 身份 | 策略名、策略方、实盘标识 | 策略方简介、可验证记录、策略说明 |
| 收益 | 年化收益、统一统计区间 | 累计收益、分周期收益、计算方法、费用口径 |
| 曲线 | 迷你净值曲线 | 可切换周期、触摸查看数值、回撤曲线、可选基准 |
| 风险 | 最大回撤、夏普比率 | 回撤持续时间、恢复时间、波动、风险限制 |
| 交易 | 交易笔数 | 胜率、盈亏比、平均持仓时间、交易品种、历史交易 |
| 运行情况 | 运行天数、当前跟随人数 | 数据更新时间、账户连接情况、执行异常记录 |
| 收费与门槛 | 必要时显示最低跟随金额或收费标记 | 服务费、分润规则、结算方式、最低金额 |
| 操作 | 跟单、收藏 | 跟单配置、管理、对比、分享 |

详情页建议按以下顺序组织：

1. **核心概览**：收益、风险、实盘状态、跟单入口。
2. **表现分析**：完整净值曲线、月度收益热力格、回撤分析。
3. **策略机制**：交易品种、持仓周期、是否使用马丁或网格、仓位管理方式。
4. **交易记录与执行表现**：历史交易、滑点、跟随偏差。
5. **策略方与收费规则**。
6. **风险说明与跟单设置**。

月度热力格必须保留正负数值；缺失月份用灰色或 `—`，不能与零收益混淆。

### 5. 跟单交互链路

建议采用 **“入口预览 → 配置 → 最终确认 → 提交状态 → 管理”**，避免用户还没看到金额和规则就先确认一次。

1. **点击“跟单”**
   - 弹出底部预览面板。
   - 展示策略名、主要交易品种、最低资金要求、费用概要。
   - 未绑定 MT5 账户时，引导绑定，并保留当前策略与流程进度。
   - 下一步文案：“设置跟单”。

2. **选择账户与资金**
   - 选择已连接的 MT5 账户，展示账户币种和可用资金。
   - 输入跟随资金或风险预算。
   - 明确说明该金额是**真实划拨的资金**，还是**用于计算仓位的预算**；两者不能混称“投入金额”。
   - 若只是预算，不应让用户误以为其天然构成最大亏损上限。

3. **设置风险与执行参数**
   - 基础项：仓位缩放方式、最大跟随仓位、亏损停止阈值。
   - 高级项折叠：品种限制、滑点限制、是否跟随当前已有持仓。
   - 默认仅跟随新开仓；如支持同步已有持仓，说明实际入场价格可能不同。
   - 每个阈值必须写清触发动作，例如“停止新跟单”还是“尝试平掉已有跟随仓位”。
   - 若后端不支持某个控制，不应在界面上提供一个无法执行的设置。

4. **最终确认**
   - 汇总策略、账户、资金口径、仓位比例、停止条件、费用。
   - 用简短文字说明：跟随成交可能与策略方不同，止损阈值不保证精确成交。
   - 按钮写“确认开启跟单”；如涉及转账，文案必须同时体现资金动作。

5. **提交与反馈**
   - 点击后进入“正在提交”，防止重复提交。
   - 服务端确认建立跟随关系后，显示“跟随中”。
   - 尚未有符合条件的新交易时，显示“已开启 · 等待新交易”，不要让用户以为提交失败。
   - 网络超时先查询状态，提供“查询结果”，避免直接让用户重复开启。

6. **跟单后的管理**
   - 展示实际跟随盈亏、当前仓位、跟随状态和异常提示。
   - 提供“调整参数”“暂停新跟单”“终止跟单”。
   - 暂停或终止时，明确已有仓位如何处理；涉及平仓时展示具体仓位并确认，不能将其藏在一个含糊的“取消”按钮后面。

## 任务 B：OTFAX 前端的卡片化交易设计

以下按卡片化交易终端的一般设计方法展开，不将未核实的视觉特征归因于 OTFAX／OTFX。

### 1. 卡片视觉手法

卡片的价值是把**一个交易对象及其指标、状态、动作放在同一组里**。专业感主要来自信息对齐和层次，而不是阴影数量。

建议采用以下基础规范：

| 元素 | 建议规范 |
|---|---|
| 页面背景 | `background: #F5F6F8` |
| 卡片表面 | `background: #FFFFFF` |
| 圆角 | 策略卡 `border-radius: 20px`；紧凑持仓卡 `12–16px` |
| 描边 | `border: 1px solid #E7E9EE` |
| 阴影 | 可选 `box-shadow: 0 2px 8px rgba(16,24,40,.04)` |
| 内边距 | `padding: 16px`，重点概览卡可用 `20px` |
| 卡片间距 | `gap: 12px` |
| 内部字段间距 | 紧密关联字段 `4–6px`；指标组之间 `12–16px` |
| 图标 | `18–20px`，统一线条粗细与视觉风格 |
| 操作区域 | iOS 触控热区至少 `44 × 44pt` |

执行要点：

- 使用**浅边框或轻阴影**建立边界，不要同时叠加强阴影、粗描边和大渐变。
- 每张卡一个主要数字区域，其余指标组成明确的两列或三列。
- 标签在上、数字在下；同一行数字基线对齐。
- 尽量通过留白分组，只有费用区、操作区等明显不同的内容才加分割线。
- 资产总览可以是一张大卡；大量订单或成交记录继续用紧凑列表，没必要把每一行都装成独立卡片。
- CSS 数值可用于视觉映射；原生 iOS 实现按逻辑点和动态字体适配，避免固定高度截断内容。

### 2. 数字排版

**正文使用系统字体，数字启用等宽数字特性**，不必整页改成代码字体。

```css
font-family: -apple-system, BlinkMacSystemFont, "SF Pro Text", sans-serif;
font-variant-numeric: tabular-nums lining-nums;
font-weight: 600;
letter-spacing: -0.02em;
```

具体规则：

- **对齐**
  - 独立指标卡：标签与数字统一左对齐。
  - 多行金额或交易记录：数字右对齐。
  - 小数位一致时，自然形成小数点对齐。
- **字号**
  - 总资产、核心收益：`28–34px`。
  - 次级金额与指标：`18–22px`。
  - 标签、单位：`12–14px`。
- **正负号**
  - 收益显示 `+1,268.50`、`−856.20`，颜色之外仍有符号区分。
  - 资产余额通常不加正号，也不因余额大于零就染红。
- **精度**
  - 展示金额一般保留两位，按币种规则调整。
  - 收益率、回撤、夏普通常保留两位。
  - 交易笔数、人数使用整数。
  - 报价、手数按品种与账户实际精度显示，不能统一截成两位。
- **分隔与单位**
  - 使用本地化千分位，如 `128,640.50`。
  - 多币种场景明确标注 `USD`、`USDT`、`CNY`，避免只用含义不清的 `$`。
  - 列表可缩写大金额，详情、下单与确认界面展示完整数值。
- **实时更新**
  - 预留数字宽度，防止跳动。
  - 价格变化可短暂淡色高亮，避免数字滚轮和持续闪烁。
  - 缺失值显示 `—`；真实零值才显示 `0.00`。

### 3. 配色纪律

可以把视觉面积控制为以下大致比例，但不必机械计算：

- **中性背景与表面：约 80%**
  - 页面底色、卡片、分隔线、大部分留白。
- **文字与中性图标：约 12%**
  - 主文字 `#182230`。
  - 次级文字 `#667085`。
- **品牌橙：约 5%**
  - 主按钮、选中导航、筛选选中态、关键进度。
- **涨跌与状态色：约 3%**
  - 收益数字、曲线、必要状态提示。

最重要的是固定语义：

| 颜色 | 用途 | 避免 |
|---|---|---|
| 橙色 `#FF6A1A` | 跟单、确认、当前选中 | 用来表示盈利 |
| 红色 `#D92D20` | 中国习惯下的上涨、正收益 | 把所有重要数字都染红 |
| 绿色 `#15803D` | 下跌、负收益 | 单独用绿点表示系统正常，造成歧义 |
| 中性深灰 | 余额、交易笔数、夏普、普通风险指标 | 全部弱化成浅灰 |
| 明确的图标＋文字 | 错误、成功、暂停、异常 | 只靠颜色表达状态 |

两个细节值得单独处理：

- **品牌橙底上的小号白字要检查对比度。**可保留 `#FF6A1A` 作为品牌色，按钮采用更深的橙色，例如 `#C2410C`，或为原橙色搭配深色文字。
- “上涨红色”和“错误红色”可以共存，但错误必须同时带错误图标、说明及处理入口；不要让用户仅凭红色判断含义。

### 4. 分组节奏

避免拥挤的核心是：**用页面分区表达层级，让卡片只承担对象边界。**

推荐页面节奏：

```text
页面标题／账户选择

资产概览
[          一张宽幅概览卡          ]

我的跟随                  查看全部
[          紧凑跟随摘要            ]

策略广场
[搜索] [筛选] [排序] [对比]

[          策略卡片 A             ]
[          策略卡片 B             ]
```

可执行规范：

- 页面左右边距：`16–20px`。
- 同一分组内卡片间距：`12px`。
- 不同分组之间：`24–32px`。
- 分组标题到内容：`10–12px`。
- 标题直接放在页面背景上，不额外包一层卡片。
- 同类策略卡使用一致的字段位置和曲线高度，让用户上下扫读比较。
- 总览卡可以更大，持仓摘要更紧凑，策略卡保持中等密度；不要让所有模块都一样高。
- 不建议将主要策略列表做成横向轮播，会隐藏选项，也不便比较。
- 空状态使用一块简洁说明和一个明确动作，不堆多个空白卡片。
- 支持动态字体时允许卡片增高；辅助字段可换行，收益、风险和操作入口不能被截断。

牛牛 AI 可以据此形成稳定的视觉识别：**橙色指引操作，红绿表达盈亏，统一对齐的数字和留白建立交易终端的专业感。**
