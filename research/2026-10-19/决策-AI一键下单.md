# 决策 · AI 副驾驶「一键下单」产品规格

> 2026-10-19 Sera 当场拍板。这是后续 Prompt 库、生态库、教程施工的**基准**，别再改回「只读建议」。

## 1. 决策一句话

AI 副驾驶不只是聊天：它给出交易建议，**建议卡片上带一个「一键下单」按钮**，用户点一下（经二次确认）就通过桥接 EA 下单。用户不需要手动校准手数、止损、止盈。

## 2. 交互流程（对话式下单）

```
用户：「帮我看看 EURUSD 能不能做多」
  ↓
AI 分析（行情 / 持仓 / 账户）→ 生成【下单建议卡片】
  卡片内容：
    · 品种 EURUSD
    · 方向 买入 BUY
    · 入场价（当前 ask）
    · 止损价 / 止盈价（由系统按 ATR 或固定点算）
    · 手数（由系统按「风险% × 余额 ÷ 止损距离」算）
    · 一句理由（为什么是这个点位）
    · 风险提示（这笔最多亏多少钱）
  ↓
用户点【一键下单】按钮
  ↓
二次确认弹窗（完整参数 + 「确认下单」/「取消」）
  ↓
确认 → 走桥接 EA 下单 → 回执跟踪（已受理 → 已成交/已拒绝/待核对）
```

## 3. 硬边界（这是安全底线，不是可选项）

1. **手数的算术永远由确定性程序算**，公式：`手数 = (余额 × 风险% ) ÷ (止损点数 × 每点价值)`。AI **不做算术**，只把系统算好的结果展示在卡片上。
   - 「AI 算手数」开关的真实含义：**开** = AI 建议里直接给出具体手数（该手数仍是系统算的）；**关** = AI 只给方向/点位/止损止盈，手数栏留空让用户填。
   - 换句话说：无论开关怎么摆，**模型都不碰数字计算**。这一点对小白用户是安全感，不是限制。
2. **AI 不能直接下单**。必须经过「建议卡片 → 一键下单按钮 → 二次确认」这条人工确认链。对话里说「好的我帮你买」不等于下单。
3. **止损必填**。AI 给的每个建议都必须带止损，没有止损的建议不给「一键下单」按钮。
4. **测试阶段只允许模拟账户**（沿用 EA 的 `InpDemoOnly` 闸门）。
5. **AI 明确「不给」的东西**：不预测价格、不承诺收益、不喊单、不推荐具体品种当「稳赚」、数据不足时明说不知道、不编造行情/收益数字。

## 4. AI 副驾驶的 Prompt 模板（首批）

系统身份 + 能力边界 + 建议产出格式。每个建议必须落到「卡片字段」这个结构里，才能被前端渲染成一键下单卡片：

```
你是牛牛 AI 的交易副驾驶。你的任务是在用户询问时，给出一笔「可执行的下单建议」。
输出建议时必须用下面的 JSON 结构（方便前端渲染成一键下单卡片）：

{
  "symbol": "...",          // 品种
  "side": "BUY|SELL",       // 方向
  "reason": "...",          // 一句话理由
  "risk_pct": 0.5,          // 建议的单笔风险%，默认 0.5
  "sl_points": 0,           // 止损点数（point），由你建议，系统会校验
  "tp_points": 0,           // 止盈点数（point），可为 0
  "confidence": "high|mid|low",  // 你的把握（定性，不是百分比）
  "data_note": "..."        // 数据不足时在这里说明，而不是硬给一个点位
}

红线：
- 手数你不要算，系统会算；你只给 risk_pct。
- 没有止损就不给建议。
- 数据不足 / 无法判断时，confidence=low 并说明，禁止硬给点位。
- 不预测价格，不说「会涨到 X」，不承诺收益。
- 每一条建议末尾必须带风险提示。
```

## 5. 前端要做的（落地到 p-ai 页）

- 对话流里识别「下单建议卡片」（AI 返回结构化 JSON → 渲染成卡片，不是纯文本）。
- 卡片上「一键下单」按钮 → 二次确认弹窗 → 调 `window.nn.sendCommand({type:'ORDER_MARKET', payload:{...}})`。
- 「AI 算手数」开关放设置页（p-settings），默认**开**（Sera 拍板）。
- 手数展示但标注「由系统按风险 % 计算」，让用户知道这不是 AI 拍脑袋的数。

## 6. 与现有交易链的对接

- 下单原语就是已有的 `ORDER_MARKET`（symbol / side / volume_lots / sl_points / tp_points / max_deviation_points / comment）。
- 二次确认 = 前端弹窗，不改桥协议、不改 EA。
- 回执复用现有 `commandStatus` 轮询，状态徽章一致（已受理/已成交/已拒绝/待核对）。

## 7. 明确不做（防止范围蔓延）

- 不做「AI 全自动下单」（无人工确认的自动交易）。
- 不做「AI 替你决定加仓/减仓」。
- 不做「AI 承诺收益/预测价格」。
- v1 只做「单一品种、市价、带止损」的一键下单，不做挂单、不做多品种组合。
