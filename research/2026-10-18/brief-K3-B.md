## 1. 任务背景
桌面客户端的「策略广场」目前是占位卡。要把它设计成**有内容、可浏览、可对比、可跟单**的真实页面。
参考对象已经明确：**minara 的 Strategy Marketplace / Top Strategies / 详情页七段结构**，以及 **AlphaFox 的策略排行榜 + 复制/跟单按钮**。
但我们的执行端是 **MT5 + 桥接 EA**，客户资金在客户自己的 MT5 账户里（天然非托管），所以「跑起来」的语义与加密货币完全不同。

## 2. 你要回答的设计问题

### B1 · 入口结构：要不要「双视图」？
minara 用 **Top Strategies（榜单比对）+ Marketplace（全目录检索）** 两个视图通向同一个详情页；
AlphaFox 用**一个「广场」**里并列「策略排行榜」和「带单员广场」两个池。
请给出结论：**我们做几个视图、叫什么、怎么切换**。要考虑：
- 我们内容量初期很少（可能只有 20~40 个模板），榜单视图会不会显得空？
- 简洁是硬要求（复杂内容必须下沉二级菜单），双视图是否违背？
- 给出推荐的**一级导航位置**（侧边栏 / 页面内分段控件）与理由。

### B2 · 筛选器：从 8 个维度收缩到能用
minara 的筛选维度有 8 个（Category / Asset / Sort by / Style / Risk / Availability / Creator / Direction）。
请用「默认极简 + 二级展开」的思路重做：
- **一级**（默认可见，最多 3 个）放什么？为什么？
- **二级**（点开筛选面板才出现）放什么？
- 排序选项给几个？默认值是哪个？（注意 AlphaFox 的教训：默认 7 天收益会让用户误判，所以要设计**默认周期**）
- 设计一个「快捷组合」（例如「稳健收益 / 日内活跃 / 高风险高弹性」这类预设标签），说明每个预设背后对应的筛选组合——这是让人「愿意上手」的关键。

### B3 · 卡片字段分级（三层）
明确每一层放什么、不多不少：
- **一级（扫一眼用，2~3 个）**：策略名 + 什么？（参考 minara：窗口收益 / 最大回撤 / 夏普；AlphaFox：收益率 / 跟随人数 / 运行天数）
- **二级（决定是否点进去）**
- **三级（只有详情页才看）**
必须说明：**为什么最大回撤要和收益并列**（两个对标平台都强调「先看回撤再看收益」），以及**「回测 / 模拟盘 / 实盘」三种绩效在卡片上怎么区分**（用标签？用不同颜色？还是干脆不混在同一张卡？——这是最容易被用户误读的地方，必须给明确结论）。
另外：给出**缩略图的画法**（曲线要不要放体量对比基准？要不要标发布点？K 线还是资金曲线？）。

### B4 · 详情页信息架构（逐段）
参考 minara 详情页 7 段，重排成**我们的版本**（把「My live run」改成我们 MT5 场景对应物）。
对每一段给出：标题、放什么字段、不放什么、折叠/展开策略（哪些默认收起）。
必须包含：
- **绩效三段披露**：回测 / 发布点（什么时候开始可验证）/ 实盘段，怎么画才不会被误读成一条连续曲线。
- **「运行须知」**：这个策略需要哪种 MT5 账户模式（netting / hedging）、最小资金、建议手数、不能碰的时段（新闻 / 隔夜）——这些是我们才有、别人没有的信息，**要求两平台没有但我们必须有的额外 3~5 段**。
- **「我该怎么开始」**：从详情页到真在自己 MT5 上跑起来的**完整动作序列**。

### B5 · 交互链路（最重要）
画出从浏览到停手的全链路，逐步列出：
`进入广场 → 筛选/搜索 → 看卡片 → 看详情 → (预览/收藏) → 选择参数 → 选择我的 MT5 账户 → 资金校验 → 模拟盘试运行 → 确认启动 → 运行中监控 → 暂停/停止/修改 → 停止后资产处置说明`
每一步要给出：
- 界面上**用户看到什么**（一句话）
- **系统校验什么**（可用性 / 资金 / 权限 / 版本兼容性）
- **失败时怎么提示**（不要放点了没反应的按钮：不可用要 disabled 并说明原因，参见牛牛AI 现有 AI 状态条的做法）
- **哪些步骤必须二次确认**（真金白银的动作一律要）

特别回答两个 MT5 特有问题：
1. AlphaFox 规定「一个交易账户同一时间只能被一个运行中的策略使用」。我们在 MT5 上要不要照做？给出结论与理由（考虑 netting/hedging、多个 magic number、保证金争抢）。
2. **停止策略时，已开持仓怎么办**？（mojo 的做法是停止 Agent 不会自动平仓）给出我们的默认行为 + 必须提示的话术。

### B6 · 视觉语言（要能直接写 CSS 的量）
- 配色：品牌橙 `#FF6A1A` / 深海蓝 `#2563EB` / 翡翠绿 `#0E9F5A` / 紫罗兰 `#7C3AED` 四套主色，与日/夜正交；**涨红跌绿**（浅色 `--up:#E23B2E --down:#17995B`；深色 `--up:#FF7A66 --down:#3DDC97`）。
- 硬禁令：花哨渐变、玻璃拟态、Neon 赛博、动态背景。**资金曲线在深色下用什么颜色？**（此前我们有结论：深色下净值曲线用亮蓝 `#7CA9F8`，避免被误读成单次涨跌——请复核这条是否合理。）
- 给出：**卡片圆角/间距/边框色/字号层级的具体数值建议**（浅色 + 深色两套），以及**这套数值如何与现有 `src/ui/index.html` 的变量体系对齐**（不要另起一套）。
- 给出 3 个关键组件的 HTML+CSS 片段：① 策略卡片 ② 绩效指标条（年化/夏普/回撤/笔数）③ 详情页顶部三段式曲线容器。要求：片段可直接进现有单文件 UI，用现有 CSS 变量名，不用 inline onclick。

### B7 · 「不放什么」清单
至少 8 条。参考两家平台的克制做法（例如 minara 反复声明「高排名不是推荐」「保守标签不保证回撤」），我们这里必须不放的东西（如：不放年化>XX% 的营销标签、不放无法验证的未来收益、不放「稳赚」类文案等）。每条写清风险与设计替代方案。
