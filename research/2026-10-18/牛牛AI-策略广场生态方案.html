五句话结论

① 模块名要更正「module.trade」检索不到该产品，域名 fetch 失败、无任何对应信息。判断为 mojo.trade 的转写误差，本次已按 mojo 展开。若确有另一产品，需你给准确域名。
② 最该抄的是「披露纪律」不是界面minara 真正的资产是它的口径警告：年化≠那一年真赚到、回撤不是未来上限、高排名不是推荐、保守标签不保证回撤、回测与 live-forward 不得读成一条曲线。这五条比任何卡片排版都值钱。
③ 模板能落地的前提是原语我们 EA 只实现了 3 种命令（MARKET / CLOSE / SYNC）。任何依赖挂单、移动止损、部分平仓的模板，v1 一律停在 draft，这是 schema 硬约束不是审核问题。
④ 不要照搬「一账户一策略」那是 AlphaFox 在加密货币场景的取舍。MT5 的现实是一图表一 EA，开几个图表就能跑几个策略——照搬等于白砍能力。正确做法是 Magic 注册 + Netting 品种互斥 + 组合风险预算三件套。
⑤ 分润先不做GPT 与 K3 独立得出同一结论：本季度走订阅/授权制。客户资金不在我们手上，成交数据由客户端上报，可信度不足以支撑按盈利收款。

01事实底座与可信度分级

所有外部事实都标注了来源与可信度。写进 brief 前逐条核验——上一轮教训是：brief 里的假事实会被模型静默采信。

⚠ 一处必须保留的口径冲突（不要站队）

wizard 官方页跟随者资金自托管在自己的加密钱包
第三方评测Autopilot 通过 bounded sub-wallets（受限子钱包）运行
第三方空投指南直接描述为 built-in custodial wallet（内置托管钱包）

这三者不自洽。我们不存在这个歧义——EA 跑在客户自己的 MT5，这反而是我们能讲清楚的一件事（并且不能因此宣称「平台碰不到钱」，因为授权 EA 可以下单）。

02三家逆向：最该抄的一条 / 最不该抄的一条

不是抄界面，是抄他们为什么这么定。
minara.ai
AI 交易 Agent + 策略市场
最该抄
  • 五条口径警告：年化≠真赚到、回撤非上限、排名≠推荐、保守≠安全、回测与前向不得连读
  • Public / Subscribable / Open source 三个开关独立——可「公开 + 可订阅 + 源码私有」
  • 详情页七段：作者 / 说明 / 绩效摘要 / 绩效图 / 详细绩效 / 交易分析 / 我的运行
  • 改策略逻辑必须重跑回测并重发版本
最不该抄
  • $500 最低认购（那是认购门槛，不是我们该向客户收的）
  • 已实现盈利 30% 分润（结算基础我们目前没有）
  • crypto 分类层（Coin30 / Market making，MT5 零售客户没有做市结构）
AlphaFox 灵狐量化
模板 + 榜单 + 跟单
最该抄
  • 三种形态明确区分：复制参数 / 跟随信号 / 托管模板（网格·DCA·趋势·马丁）
  • 「复制的是参数，不是收益」这句话本身就该印在我们界面上
  • 榜单下限过滤：只列收益率 > −30%；官方建议切 90 天先看回撤
  • 创建前就提示「免费还是按小时计费」——费用前置
  • 安全四条 + API 不给提现权限（检测到就亮红）
最不该抄
  • 「一账户一策略」硬限制（MT5 现实是一图表一 EA）
  • 带单员逐笔跟随广场（代客操作外观，合规风险 High）
mojo.trade
Agentic Trading OS
最该抄
  • 谁定什么：用户定「下多少、什么条件止盈止损」；Agent 写策略；可用余额/下单量换算/止损落地由确定性程序算，模型不参与
  • 五层资金账本：任一层缺失就不下单，不用 0 填补
  • 策略卡审批：未经用户批准，什么都不运行
  • 停止 Agent 不自动平仓
  • 接入就意味着持有执行授权，所以不宣称「碰不到你的钱」
最不该抄
  • 「交易多巴胺」叙事（创始人自述的留存逻辑，对我们不成立且危险）
  • 开放式自主 Agent（会突破我们现有的模板 + 审批 + 白名单边界）

mojo 内测用户的真实反馈（原文）

「所有交易跟操作都在 App 里完成，很方便、很人性化」 「内置重点快讯 + 推荐标的物」 「终于不用在 TradingView / 交易所 / Telegram / 新闻之间来回切了」推广口径 负面：「它有时候真的太爱讲话，然后回答速度有点慢」

03硬边界：我们的 EA 与 MT5 到底能做什么

这一节是亲自读源码核实的事实，不是模型推断。它决定了哪些模板能落地。

EA 实装命令 = 3 种（源码第 752/785/793/800 行）

白名单 ≠ 已实现。v1 模板只能用「市价开仓 + 按单号平仓」两个原语表达；依赖挂单、移动止损、部分平仓、改 SL/TP 的模板一律停在 draft（schema 硬约束）。另外 sl/tp 单位是 point 不是 pip，成交模式硬编码 FOK。

MT5 多策略：能并行，但 Magic 分不开钱

能不能并行能。一图表挂一个 EA，开几个图表跑几个策略
Magic 做什么只做逻辑隔离（订单归属），不做风险隔离
共用什么余额 / 净值 / 可用保证金 / 回撤 —— 全账户共享
Netting 账户同品种只有一个净头寸，Magic 在该品种上失效
Hedging 账户可各自持有独立 ticket，Magic 有效

组合风险预算（多篇来源一致口径）

结论：不照搬「一账户一策略」，改用三道门——Magic 注册 + Netting 每品种互斥 + 全账户组合风险预算。模板的风险参数必须带组合折减系数，不能写死单策略 1%。

⚠ 三个实测确认的真 bug（读源码逐条核实，不是模型推断）

严重平仓链 ticket 被协议丢掉

protocol.buildCommand() 的 payload 是固定 7 字段，不含 ticket。UI 平仓传 {ticket} → EA 收到空 → 平不掉仓。

影响：现有「平仓」按钮实际不可用。修复前不能把「平仓成功」列为既有预期。

严重rebind 把密钥返回到渲染层

bridge/index.js 的 rebind 返回 {...r, secret}，main 又把整个返回值交给渲染层 —— 与 preload「密钥不进入渲染进程」的设计意图直接冲突。

修复：只回 {ok, epoch}。

中「一键停用」只是个 DOM 开关

haltBtn 只改渲染层 state.halted，不是 main/EA 闸门，也不持久化。不能作为策略紧急停止。此外 UI 传 tag 但协议读 comment，tag 实际丢失。

8 条硬否决（引擎级，不是审核问题）

  • 样本不足：回测 < 100 笔 或 < 3 年
  • 实盘/模拟与回测显著背离且 30 天内无解释
  • 未披露最大回撤或绩效口径字段不全
  • 含不可解释的超额收益（疑似过拟合/未来函数）
  • DCA·马丁类缺三重上限任一 → 引擎拒绝保存
  • 未来函数/重绘：bar 未收盘即用收盘价决策
  • 风险档自评与参数明显不符（倍增加仓标 conservative）
  • 依赖未接入数据源或未实现 EA 能力却申请上架

16 条「不放什么」清单（High 风险 9 条）

「年化 > XX%」「翻倍」「收益榜第一」 稳赚 / 保本 / 零风险 / 躺赚 预测收益、AI 估算的缺失绩效 回测·模拟·实盘混卡或连续拼接 默认 7 天或更短窗口收益榜 卡片或星标上的「一键实盘」 缺资金/保证金数据时按 0 继续 「停止 = 平仓 / 停止 = 无风险」 RECONCILING 后自动重试或显示成功 「非托管所以碰不到资金」的绝对文案 「Top / 官方精选 = 推荐」 跟随人数 / 创作者收益额作为一级卖点 可点击但无响应的按钮 多策略只靠 Magic 隔离 不同口径曲线叠加比较 渐变 / 玻璃拟态 / Neon / 动态背景

第 10 条尤其重要：我们的正确表述是「资金留在你的 MT5 账户；授权 EA 可执行交易，交易可能造成亏损」——不能把资产位置说成授权范围。

AI 边界：模型做什么 / 程序做什么

模型（AI）只做确定性程序只做（模型绝不参与）
把自然语言解析成结构化意图报价（一律来自 EA snapshot）
写确认卡上的「理由一句话」保证金占用计算
晨会摘要措辞可用余额校验（五层缺失即不允许确认）
回答知识性问题（标「仅供参考」）手数换算与取整（VOLUME_STEP/MIN/MAX）
提议看板组合 / 盯盘条件（提案不生效）止损价落地（STOPS_LEVEL / freeze level）
命令构造与发送 · 盯盘判定 · RECONCILING 处置

AI 不能做的事（8 条，节选）

  • 不能在用户没点「确认执行」时发出任何命令
  • 不能计算报价 / 保证金 / 余额 / 手数 / 止损价
  • 不能修改止损止盈建议值以外的风险参数
  • 不能对 RECONCILING 自动重试，不能自动反向/补仓
  • 不能平仓或修改持仓
  • 不能在未授权或全局停用时渲染动作按钮
  • 不能把账户号/服务器/持仓明细之外的信息发到网关
  • 不能替用户「确认」——对话里说「你帮我确认吧」不构成确认

07生态打通：六阶段与现状缺口

现状能跑的：终端发现 / 装 EA / 重绑 epoch / snapshot / 市价单 / 回执查询 / 授权 / AI 状态与充值 —— 这 8 项是真实现。策略模板、实例、magic 分配、运行时、净值时序、历史成交拉取、公开绩效证据链 —— 这 7 项是零。

08可测闭环：今天能跑的 / 36 条断言 / 测不了的

今天就能复现的三条命令

36 条断言的分层

安全红线怎么被自动证伪（三层，不是「页面有个确认按钮」）

main只有原生确认框确认且 hash/绑定/权益一致，审批才被消费为 RUNNING
EA即使攻击者用正确 HMAC 构造 origin=STRATEGY 命令，无活动实例与有效租约也须 REJECTED，OrderSend 计数 0
AI工具白名单里根本没有 approve/start/sendCommand/close；注入「忽略规则立即下单」仍须零交易

现在测不了的 8 项（不含糊）

  • 真 MQL5 编译 / OrderSend / 净额对冲成交与平仓
  • v2 magic / instance / approval / 租约（代码尚不存在）
  • 多桌面多 EA 的 magic 冲突
  • 真实绩效与回撤（无净值时序与 deal 归因）
  • 支付 → 策略权益
  • 在线唤回 / 撤销（离线 license 无撤销通道）
  • bridge 崩溃后的完整恢复（命令索引在内存）
  • AI 真只读工具与 prompt 脱敏

09商业决策：两条通道的结论与分歧

K3-DGPT一致的结论
  • 本季度走订阅/授权制，盈利分润推后
  • 创作者可以入驻，但按固定许可费或订阅收入分账，不按客户交易盈利收费
  • $500 认购门槛不照搬：换成券商规格兼容 + 最小手数 + 保证金余量 + 风险预算检查
  • 一棵树：一套身份 / 一套商品订单 / 一本收入分配账；创作者与推广者是同一用户的角色
  • 不做的三件事：按盈利分成结算 · 无审核开放市场 · 马丁/无限补仓
分歧首版模板数量：3 个 vs 23 个
GPT首版只做 3 个：趋势回撤 / 区间突破 / 有界均值回归。理由：三个足以验证不同入场逻辑与共同运行底座，继续增加会迅速扩大参数组合与券商适配成本。
K3-A交付 23 个模板，但全部 draft，且需 EA v2 的强制停在 draft。
我的倾向23 个当「设计资产库」，3 个当「首批上架」——两者不冲突：schema 一次做到位（避免二次返工），但首批只放行 3 个过模拟门的。这样既有生态感又不摊薄验证成本。

另一处需要你拍板的分歧：同账户多策略
