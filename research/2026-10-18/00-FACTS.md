### 1.1 两个发现视图
- **Top Strategies**：榜单比对。两种排序视角：**Consistent**（稳）/ **Aggressive**（激进）；顶部累积收益对比图（滚动窗口）；列表展示年化收益、窗口收益、夏普、最大回撤、交易笔数、测量窗口；右列放热门创作者与新提交。
- **Marketplace**：全目录检索 + 多维过滤。通往同一个详情页。

### 1.2 卡片字段（Marketplace）
策略名 + 市场、创作者、**该窗口收益**、**最大回撤**、**夏普**、**窗口长度**、**Share（创作者分润比例）**；小图为窗口内收益走势。
卡片动作：**星标（存 Starred，不下单）**、**Run（进入订阅与部署流程）**。

### 1.3 筛选维度（8 个）
| 维度 | 取值 |
|---|---|
| Category | All / **Time-Series（时序）** / **Cross-Sectional（截面）** |
| Asset | TradFi 30、Coin 30、Coin 50 等资产组 + 单个标的 |
| Sort by | Featured / APY / Sharpe / Calmar / Max DD |
| Style | **Trend following、Swing、Mean reversion、Breakout、Arbitrage、Market making、Other** |
| Risk | **Conservative / Balanced / Aggressive**（创作者自评标签） |
| Availability | All / **Subscribable** / **Open source** |
| Creator | All / Verified |
| Direction | 可做多/做空/方向过滤 |

### 1.4 详情页信息架构（7 段）
1. **Author info**：谁发布的、发过几个策略、是否上过 Top Strategies。
2. **Strategy info**：创作者对规则/变更的描述。
3. **Performance summary**：总收益、年化、胜率、最大单笔盈利、夏普、最大回撤。
4. **Performance chart**：**回测段 + 正式发布标记（Publish marker）+ live-forward 段**。官方明确要求：**不得把回测段和 live-forward 段当成一条连续的实盘曲线读**。
5. **Detailed performance**：收益、期望收益、手续费、多空分列、回撤、Sharpe、Sortino、Calmar。
6. **Trades analysis**：笔数、多空占比、胜率、平均盈亏、profit factor、连胜连败。
7. **My live run**：我是否已运行、启动/停止控件。

关键口径（官方原话要点）：
- **Window Return** = 展示窗口内的总结果；**Annualized Return** 由该窗口折算成年化；短窗口高收益年化后会非常大，官方明确警告「年化 ≠ 这一年真赚到」。
- **Max Drawdown** = 该记录内最大峰谷回落，**不是未来损失上限**。
- 排名会因**滚动窗口刷新**而变化，即使创作者没改策略。
- 榜单高排名 **不是** Minara 的推荐。
- Conservative 标签 **不保证** 回撤可控。

### 1.5 可见性三段独立开关
- **Public**：可被发现/查看。
- **Subscribable**：可被订阅并运行（源码仍可私有）。
- **Open source**：可见并可 fork 源码。
三者互相独立：「Public + Subscribable + 源码私有」是允许的常态。

### 1.6 商业与结算条款（wizard.minara.ai + 官方 FAQ）
- **最低认购**：订阅他人策略 **至少 $500**（创作者可自行提高，如 $1000）；自建策略走 Autopilot 也适用同样的 $500 下限。
- **创作者分润**：订阅者**已实现盈利**的 **最高 30%**，按创作者等级；**亏损期不分润**。
- **结算周期**：创作者自选 **每周一 / 每两周 / 每月 1 号**；跟随者停止跟随时也会触发一次结算。
- 创作者可在编辑器里设置：分润比例、最低/最高投资额、**订阅者上限**。
- 订阅者资金 **自托管在自己的钱包里**，平台不碰钱（我们的 MT5 场景天然满足：EA 跑在客户自己的 MT5）。
- 星级 / 关注 **不会** 触发任何资金动作。

## 二、Mojo（mojo.trade）——「看板 DIY + 策略卡审批 + 执行留痕」的对标本体

来源：https://www.mojo.trade （官网多屏实拍说明）+ https://news.cnyes.com/news/id/6629486 （创始人访谈）+ https://nitter.space/COMMA_LLL （内测用户反馈）+ https://tokenpost.com/news/regulation/30112

### 2.1 六大能力（官方目录）
Research（把行情/链上信号/上下文拉进同一段对话）、Charts（要图就给图并标注关键位）、**Boards（描述式自建看板）**、Watch（设条件让 Agent 盯盘）、Trade（把想法变成**可审阅、可批准**的计划）、Review（追溯信号/决策/动作）。
它们**共享同一段对话**，上下文从「提问」无缝带到「计划」。

### 2.2 审批与控制（核心可抄）
1. **Review before it starts**：每个策略都展示**场所、条件、仓位、风控**；**未经你批准，什么都不运行**。
2. **See everything it does**：可随时打开任一 Agent，查看状态、你批准过的计划、以及它记录的活动。
3. **Step in at any time**：带确认地改参数、暂停或停止；**停止 Agent 不会自动平掉已开仓的仓位**。
4. **Strategy card**：请求被转译成一张「策略卡」，你在卡上确认手数与止损后才启动。

### 2.3 创始人自述的架构取舍（访谈原文要点，信息密度极高）
- **「下一代交易所不再区分 DEX 和 CEX」（创始人访谈主题）：Mojo 把「链上登记的币 + 交易所有现货交易对的币（约 1.3 万+）」放进同一个列表和搜索框；并指出 **DEX/CEX 的区分会悄悄渗透进产品的每个角落，必须在架构层专门处理**。
- **用户体验取舍**：交易对多数用户而言最要紧的两件事是——**自己拿主意的感觉**，和**拿完主意之后马上看到的反馈**。导航式产品给的是回测曲线和研究报告（反馈迟钝），全自动机器人把「拿主意」也拿走了；用户留不下来很多时候是因为**交易里的多巴胺没了**。因此 Mojo 在**用户流程、交互方式、可视化**上花的功夫远多于一般 AI 产品。目标用户是**已经在交易、有自己方法的人**，决定权一直在用户手里：分析直接画在 K 线上、信号实时推到网页和手机、赚钱可一键生成分享海报。
- **资金账本五层**：钱分散在交易所 / Hyperliquid / 多条链钱包；下单前必须把每个场所的**实际余额、挂单占用、其他策略已占用资金**一起算清楚。Mojo 的资金账本分五层，**任何一层数据缺失就不下单，不会用 0 去填**。
- **「谁定什么」边界**（极重要）：
  - **用户定**：下多少、什么条件止盈止损 —— **最终在策略卡上确认**；
  - **Agent 负责**：把用户的话写成策略；
  - **确定性程序算**：可用余额够不够、具体下单量怎么换算、止损价按交易所规则怎么落地 —— **模型不参与**。
- 授权诚实原则：接入用户交易所账户就意味着必须持有执行授权，**所以不会说「碰不到你的钱」这种话**；但资产留在用户自己那里，没有平台资金池。

### 2.4 内测用户反馈（真实吐槽，直接用得上）
- 正面：「所有的交易跟操作都在 App 里完成，很方便、很人性化」「还会帮我处理好跨链，只要指令下得正确」「内置重点快讯 + 推荐标的物」。
- **负面**：「它有时候真的太爱讲话，然后回答速度有点慢」。
- 另一篇报道引述的用户故事（产品叙事，非客观评测）：下单前先回溯用户历史交易行为（重复犯错的记录、自己设过却越过的规则），在此之前先问「你是在做一个决定，还是在重复一件你已经做过 4 次的事」。

## 三、AlphaFox（alphafox.app 灵狐量化）——「模板 + 榜单 + 跟单 + Agent CLI」的对标本体

来源：https://www.alphafox.app/zh 、https://www.alphafox.app/zh/docs 、https://www.alphafox.app/zh/docs/getting-started 、https://www.alphafox.app/zh/docs/faq

### 3.1 三种「拿来就用」的形态（明确区分）
- **复制（Copy）**：从**策略排行榜**上把围绕"表现稳定"的策略**一键复制到自己账户**——**复制的是参数，不是收益**，由你自己的账户独立运行。
- **跟单（Follow）**：让系统**自动跟随带单员之后的每一笔开平仓**。官方明确：**不会补开你开始跟单前已有的持仓**（所以刚建的跟单策略通常空仓，要等下一次动作）；Pro/Pro Max 提供「仓位后入」开关（亏到阈值才跟，已满足条件的仓位会直接开出来）。
- **托管模板（Templates）**：**网格、DCA、趋势、马丁** 等现成模板，7×24 自动交易。

### 3.2 榜单规则（很值得抄的"反幸存者偏差"设计）
- 榜单**只列出所选周期收益率高于 -30% 的策略**（明确的下限过滤）。
- 官方新手建议：**把周期切到 90 天以上，先看最大回撤和数据天数，别只看 7 天收益**。
- 卡片展示：策略名、跟随人数、运行天数、近 N 天收益率。
- 排行榜上的策略：**标「公开」的可复制**；**「未公开」的只展示收益指标和曲线**。
- 带单员广场（信号源）与策略排行榜（可运行的策略）**是两个不同的池**，但都叫「广场」，卡片上都有「模拟」和「跟单」按钮。

### 3.3 上手路径与安全红线（文案与设计都很成熟）
五步：注册领 3 天 Pro（可免费跑 5 个模拟策略）→ 逛排行榜（切 90 天）→ 添加**模拟交易所**（只填初始资金，**不要真实 API Key**）→ 四步创建策略（**创建前页面会告诉你这个策略是免费还是按小时计费**）→ 在我的策略里看收益曲线/持仓/订单/事件，跑顺了再考虑实盘。
安全四条：
1. 交易所 API 非托管连接（资金留在用户自己的交易所账户）；可选的 Hyperliquid 托管钱包由 **Turnkey** 托管（并明确标注区别与风险）。
2. **API 不给提现权限**：只开「读取 + 交易」，**检测到提现权限时页面亮红色警告**。
3. 历史收益不是承诺：**先看回撤，再看收益**。
4. **先模拟，再实盘**。

### 3.4 关键约束（对我们的 MT5 场景直接相关）
- **一个交易账户同一时间只能被一个运行中的策略使用**（避免两个策略在同一账户里抢仓位和保证金）；停掉后可给别的策略用；想并行跑多个策略就多准备几个账户。
- **同一账户占用约束**：跟单复制的是新信号；我们从 MT5 EA 落地时，「一个 MT5 账户 vs 多策略并行」是必须回答的架构问题。

## 五、MT5 多策略并行的事实（决定模板能否落地，2026-10-18 补充）

来源：
- https://fxea365.com/zh-CN/knowledge/multi-ea
- https://softimotrade.com/en/blog/can-you-run-multiple-expert-advisors-on-one-mt5-account
- https://www.fxbrokertrust.com/zh-cn/insights/3766
- https://www.orionrfx.com/blogs/trading-tools/run-multiple-eas-one-account

### 5.1 能不能在同一账户跑多个策略？
**技术上是：可以。** MT5 的规则是「**一个图表只能挂一个 EA**」，想跑几个就开几个图表；各图表并行执行、参数独立。
所以 AlphaFox 那条「一个账户同一时间只能一个策略」是**加密货币场景下的取舍**，不是 MT5 的现实约束——**照搬会平白砍掉我们的能力**。

### 5.2 Magic Number 只做「逻辑隔离」，不做「风险隔离」
- Magic 是 EA 发给每笔订单的整数标识，EA 只操作带自己 Magic 的持仓。Magic 重复会导致**误平**别人仓位。
- **但是**：所有 EA 共用同一个余额、净值、可用保证金、回撤。**Magic 分不开 money**。
- 一个 EA 的重仓会吃掉其他 EA 需要的保证金；一个 EA 触发的追加保证金/强制平仓，会影响整个账户。

### 5.3 Netting vs Hedging 是硬约束（我们必须处理）
- **Hedging 账户**：每个 EA 在同一品种可以各自持有独立 ticket，Magic 能有效区分。
- **Netting 账户**：**同一品种只有一个净头寸**。若 A 策略做多 EURUSD、B 策略做空 EURUSD，二者**轧差成一个仓位**——此时 **Magic 隔离在该品种上直接失效**。
- 行业建议：**一个品种只分配给一个策略**（尤其在 netting 账户）。

### 5.4 组合风险预算（多篇来源一致的口径）
| 同时运行的 EA 数 | 单个 EA 每笔风险 | 组合合计风险 |
|---|---|---|
| 1 | 1.0% | 1.0% |
| 2–3 | 0.5–0.7% | 约 1.5–2.0% |
| 4–6 | 0.3–0.5% | 约 2.0–2.5% |
| 7+ | 0.2–0.3% | 控制在 2.5% 以下 |
并需同时校验「所有 EA 同时满仓时」的保证金水位。

### 5.5 常见的翻车清单（可直接转成我们的硬校验）
1. **Magic 重复**（经典事故源：异常平仓与「鬼影单」）
2. 因为「单个看起来不错」就继续加 EA —— **每加一个都改变的是组合风险**
3. **单一货币暴露**：四个策略最后都在做空 USD，本质是同一笔宏观押注
4. **没有关停标准（kill criteria）**：没有提前定好何时关掉单个策略，衰变中的系统会悄悄吸血整个组合
5. **终端是单点故障**：本机/终端挂了，所有策略一起停（因此需要监控与告警）
6. 负载：终端卡顿会拉长「信号→下单」延迟，实际成交价偏离预期净值偏离

### 5.6 部署隔离层级（从弱到强）
同一终端多图表（共享账户，进程共享）→ **多个 MT5 实例独立目录分别登录**（进程级隔离，一个实例崩溃不影响其他，也避免指令拥挤）。

### 5.7 对我们「策略广场 / 模板体系」的直接结论（阿墨据此先行判断，供模型复核）
- 不做「一账户一策略」的硬限制；改为 **magic 注册 + 每品种互斥（netting 强制）+ 组合风险预算** 三件套。
- 「停止策略」不等于平仓；必须显式处置已有持仓（与 mojo「停止 Agent 不自动平仓」一致）。
- 模板的风险参数不能按「单策略 1%」写死，必须带**组合折减系数**。

- 正面（内测用户原话）：「过程中我完全没有使用任何钱包，所有交易跟操作都在 App 里进行」「内置重点快讯 + 推荐标的物」。
- 负面（内测用户原话）：「它有时候真的太爱讲话，然后回答速度有点慢」。
- 第三方报道（BiRun）指出行业层面的**未解难点**：自然语言到策略代码的转化准确率、Agent 执行环节的延迟与滑点控制；合规层面：AI 自主执行涉及多法域监管差异，**策略授权与用户责任划分的设计直接影响长期合规可持续性**。
