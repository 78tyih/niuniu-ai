## 0.1 事实锚点

- Minara 的 Top Strategies 与 Marketplace 通向同一详情页；卡片同时给窗口收益、最大回撤、夏普和窗口长度，详情页区分回测、发布点与 live-forward，并明确不能把回测与 live-forward 读成一条连续实盘曲线。（`00-FACTS.md §1.1–1.4`）
- Minara 明确：年化由窗口折算，不等于这一年实际所得；最大回撤不是未来损失上限；高排名不是推荐；Conservative 是创作者自评且不保证回撤。（`00-FACTS.md §1.4`）
- AlphaFox 区分复制参数与跟随信号，建议新手看 90 天以上、先看回撤和数据天数；其账户约束是一个交易账户同时只被一个运行中策略使用。（`00-FACTS.md §3.1–3.4`）
- Mojo 的策略卡在启动前确认仓位与止损；停止 Agent 不自动平仓；资金数据任一层缺失就不下单，不用 0 填充。（`00-FACTS.md §2.2–2.3`）
- MT5 可在一个账户的多图表运行多个 EA；Magic 只做订单/持仓逻辑隔离，不能隔离共享余额、净值和保证金；Netting 下同品种只有一个净头寸，Magic 无法保持策略间独立仓位语义。（`00-FACTS.md §5.1–5.4`）
- 牛牛AI 当前未授权不能下单；命令回执含 `RECONCILING`，该状态禁止自动重放并要求人工核对；渲染层 CSP 禁止 inline onclick，交互须在 `app.js` 绑定。（`01-CONTEXT.md`「桌面端已落地的能力」）
- 现有 UI 为 212px 侧边栏、六个页面，主题与 accent 正交；`.card`、`.seg`、`.lic`、`.badge`、`.modal` 等可直接复用。（`src/ui/index.html:9-209`）

## B1 · 入口结构：一个一级入口，两个页内视图

### 结论

[推断] 做 **2 个页内视图、1 个详情页、1 个一级入口**：

1. **全部策略**：默认视图，卡片目录，承担搜索、筛选、收藏与进入详情。
2. **排行对比**：同筛选条件下的表格视图，承担同口径、同窗口比较；不做固定「Top N」。
3. **策略详情**：两个视图共用，不复制详情结构；详情内「我的 MT5 运行」承担单策略监控。
4. 侧边栏只保留现有「策略广场」；视图切换放在页面标题右侧，复用现有 `.seg`，不再增加侧边栏项目。

[推断] 这不是 AlphaFox 式两个池并列：首版只做「策略模板」，不做「带单员广场」。主行动词用「使用策略 / 模拟运行 / 启动实盘」，不用容易误解为镜像他人账户的「一键跟单」。模板复制的是策略版本与参数；启动后不补开历史持仓，只处理启动后的新信号。未来若加入信号源，须另建类型、说明与链路，不能与模板共用含糊的「跟单」按钮。

### 为什么双视图但不双入口

- [推断] 卡片目录适合初期浏览；排行表适合同口径比较。两者共用筛选和详情，增加的是展示切换，不是另一套信息架构，复杂度 **Low**。
- [推断] 侧边栏是一级产品导航，视图是页面内部的二级任务，因此切换放 `.seg` 比增加「排行榜」一级菜单更符合「复杂内容下沉」。
- [推断] 不做 Top Strategies 式顶部多策略收益叠图：不同数据长度、来源和起点会让视觉比较压过实际可比性。

### 内容少时如何避免「空榜单」

- [推断] 排行不固定显示十名或二十名，而是显示当前条件下全部可比较策略；没有名次奖牌、不补占位行。
- [推断] 排行只接纳该口径、该固定窗口都有完整记录的策略；短记录仍留在「全部策略」，标「记录不足当前窗口」，不以更短窗口收益冒充当前窗口收益。
- [推断] 若当前条件下没有可比较记录，「排行对比」控件 disabled，并在旁边说明「当前筛选下暂无同口径、同窗口记录」；用户停留在有内容的全部策略页。
- [推断] 「全部可验证记录」只用于目录查看，不生成名次；因为不同策略的实际起点可能不同。
- [推断] 加载失败、筛选无结果、确实没有策略是三种不同空态：分别给「重试」「清除筛选」「暂无挂牌」，不能把加载失败伪装成无内容。

## B2 · 筛选器：三个一级控件，其余下沉

### 一级：默认可见

| 控件 | 默认值 | 理由 |
|---|---|---|
| 绩效口径 | [推断] **模拟盘**；可显式切到实盘或回测 | [推断] 与现有「模拟盘优先」一致；不同来源不混排，缺少某口径时显示空态，不自动用回测或实盘顶替。 |
| 品种 / 市场 | [推断] 全部 | [推断] MT5 执行直接受品种、合约规格与交易时段影响，这是比抽象 Category 更接近实际兼容性的筛选。 |
| 统计窗口 | [推断] **近 90 天** | AlphaFox 官方建议新手看 90 天以上而非只看 7 天收益；[推断] 所有指标、曲线和排序必须共享这个窗口。 |

[推断] 搜索框与排序控件放在同一工具行，但不计入三个筛选项；当前窗口和绩效口径始终同时可见，不能藏进「更多筛选」。卡片还必须写实际起止日期和实际记录天数。

### 二级：点「筛选」后展开

[推断] 面板分为三组，选中后在工具行生成可逐项移除的条件标签：

- **策略特征**：Style（趋势 / Swing / 均值回归 / 突破 / 套利 / 做市 / 其他）、Risk（保守 / 平衡 / 激进 / 未评级，注明评级来源）、Direction（做多 / 做空 / 双向）、持仓周期（日内 / 可隔夜 / 混合）。
- **MT5 适配**：账户模式（Netting / Hedging / 两者）、交易时段限制（避开新闻 / 不隔夜 / 无限制）、「仅看当前账户可运行」。未选择账户时，最后一项 disabled 并说明「先选择 MT5 账户」。
- **可用性**：全部 / 可模拟 / 可实盘 / 仅查看。动作不可用时仍允许阅读详情，但运行按钮 disabled 并显示原因。

[推断] 首版不把 Category（Time-Series / Cross-Sectional）做成筛选，留在详情的技术说明；不把 Creator 做成筛选，避免在内容少时增加没有检索价值的控件。后续若开放多创作者生态，再评估加入，不预设精确数量阈值。

### 排序与周期

[推断] 排序只给 4 项：

1. **最大回撤：低 → 高（默认）**。
2. 夏普：高 → 低。
3. 窗口收益：高 → 低。
4. 交易笔数：多 → 少。

[推断] 不设 Featured / 官方推荐排序；同值时依次按实际记录更长、策略名稳定排序，避免刷新时无解释跳动。窗口变化会改变结果，视图旁固定写「排序不等于推荐」。

[推断] 周期可切近 30 天、近 90 天、全部可验证记录，默认仍为近 90 天。短记录不参加固定窗口排行，不用年化值替代窗口收益，不用 0 填缺失数据。

### 快捷组合

[推断] 快捷组合只是显式筛选的别名，不改变绩效口径；点击后展开条件摘要，允许逐项移除，不暗示平台推荐。

| 预设 | 对应筛选组合 | 必须附带的解释 |
|---|---|---|
| 回撤优先 | [推断] 当前口径 + 近 90 天 + 完整窗口 + 最大回撤升序；同回撤再看记录天数 | 「历史回撤不是未来损失上限；排序不等于推荐。」 |
| 日内活跃 | [推断] 当前口径 + 近 90 天 + 持仓周期=日内 + 不隔夜 + 交易笔数降序 | 「活跃只描述交易频率，不代表盈利或低风险。」 |
| 趋势波段 | [推断] 当前口径 + 近 90 天 + 完整窗口 + Style=趋势 + 持仓周期=可隔夜 + 夏普降序 | 「波段可能承担隔夜与新闻风险，须先看运行须知。」 |

## B3 · 卡片字段三级分层

### 字段清单

| 层级 | 只放这些 | 不放这些 |
|---|---|---|
| 一级：扫一眼 | [推断] 策略名 + 绩效来源徽章；**窗口收益、最大回撤、实际记录天数**三个指标；一张资金曲线缩略图 | [推断] 年化、跟随人数、创作者收益额、多个窗口并排、营销标签 |
| 二级：决定是否点进去 | [推断] 实际窗口起止日期、夏普、交易笔数、品种/市场、风格与风险标签、账户适配摘要、可用状态 | [推断] Sortino/Calmar、连胜连败、逐笔交易、完整参数表 |
| 三级：详情页才看 | [推断] 年化及其折算说明、总收益、期望收益、费用、Sortino、Calmar、profit factor、胜率、平均盈亏、多空拆分、最大单笔盈亏、连胜连败、版本变更、完整 MT5 约束与运行记录 | [推断] 无法验证的预测收益、缺失指标的估算值 |

### 为什么最大回撤必须与收益并列

最大回撤是记录内最大峰谷回落，不是未来损失上限；Minara 与 AlphaFox 都强调先看回撤而非只看收益。（`00-FACTS.md §1.4、§3.3`）

- [推断] 单看收益会隐藏达到结果所经历的净值路径，因此回撤与收益必须同来源、同窗口、相邻且同字号，不得放到 hover 或详情页才出现。
- [推断] 最大回撤以非负幅度展示并明确标签，不与涨跌红绿混用；收益可正可负，回撤不因数值较小就获得「安全」徽章。
- [推断] 卡片固定说明「同一记录窗口 · 回撤不是未来损失上限」，详细定义放详情，不在卡片塞长文。

### 回测 / 模拟盘 / 实盘：明确结论

[推断] **不混在同一张卡，不混在同一个榜，不用一条曲线拼接；一张卡在任何时刻只有一种绩效口径。**

- [推断] 页面级「绩效口径」控制整个列表；同名策略可在不同口径视图中出现，但不能把三种指标并排放进一卡。
- [推断] 来源徽章使用明确文字「回测 / 模拟盘 / 实盘」，加实际起止日期；颜色只作辅助，不用绿色暗示实盘更好，也不用红绿暗示收益。
- [推断] 模拟盘卡片在缩略图上方重复「模拟盘，非真实资金绩效」；回测卡片写「历史规则演算，非发布后前向记录」；实盘卡片写账户记录起点，不写「官方认证收益」。
- [推断] 某口径缺数据就显示「暂无该口径记录」，相关指标为「—」；禁止用另一种口径补位。

### 缩略图画法

- [推断] 只画该策略、该口径、当前窗口的**收益率/净值曲线**，不画 K 线；K 线表达标的价格，不等同策略资产结果。
- [推断] 不叠加其他策略、指数基准、体量/AUM 或创作者账户规模；首版没有同口径基准体系时，基准线只会增加误读。
- [推断] 画一条零轴，使用完整当前窗口，不裁剪掉回撤段；不做渐变面积填充，不用上涨红、下跌绿分段染线。
- [推断] 卡片不画发布点，因为卡片本身只含一种口径；发布点在详情披露图中强制出现。若实盘卡从发布日开始，只写「发布以来 + 实际日期」。

### 三段绩效怎样画才不会误读

1. [推断] 使用三个独立图区：**回测｜发布后模拟｜发布后实盘**；在回测与前向区之间放「发布点」日期与版本标记。发布点不是收益数据。
2. [推断] 三个图区使用不同 `<figure>` 和不同 path，中间留明确间隔，不用一条 path 连接；各自写起止日期、样本口径和指标。
3. [推断] 模拟段标题必须是「发布后模拟盘 · 非真实资金绩效」；实盘段才是「发布后实盘」。模拟不能拼接成更长实盘。
4. [推断] 回测结束到发布、发布到模拟/实盘开始之间允许有真实空档；没有某段数据就显示空态，不从上一段末端延伸虚线。
5. [推断] 每段单独从各自起点计算收益、回撤和交易统计；不提供跨回测、模拟与实盘的「累计至今」数字。
6. [推断] 策略版本变化处另加版本标记；如果口径不可比，从该版本另起一段，而不是改写历史曲线。
7. [推断] 回测段用灰色虚线、模拟段用蓝色点线、实盘段用蓝色实线，同时必须有文字标签；线型和文字是主区分，颜色只是辅助。

### 「我该怎么开始」从详情页出发

[推断] 详情页固定显示八步检查清单：阅读运行须知 → 选参数 → 选已绑定 MT5 模拟账户 → 兼容性/资金校验 → 在模拟账户运行该版本 → 查看模拟记录 → 选择实盘账户并核对实盘票据 → 二次确认启动。模拟通过不会自动转实盘，任何版本或关键参数变化都使原模拟快照失效并重新生成待确认快照。

### MT5 问题 1：是否一个账户只跑一个策略

[推断] **不照搬 AlphaFox 的账户级独占。目标设计允许同一 MT5 账户运行多个牛牛AI策略，但必须同时通过以下三道门；这不是宣称当前仓库已经支持多策略。**

1. [推断] **Magic 注册**：按账户原子分配唯一 Magic；与现有运行、未决命令、残留挂单/持仓冲突时禁止启动。残留归属未清理前不回收复用。
2. [推断] **品种与账户模式互斥**：Netting 下同一品种只允许一个牛牛AI策略；若该品种已有手工或其他 EA 净头寸，归属无法可靠拆分，禁止启动或自动平仓。Hedging 下可独立 ticket，但仍须做同品种和跨品种相关敞口检查。
3. [推断] **组合风险预算**：每次新增、修改或恢复策略都重算全账户余额、净值、可用保证金、挂单占用、其他策略与手工敞口；任一层缺失即阻断。模板风险参数必须按当前组合折减，不能写死单策略风险值。

[推断] 这样保留 MT5 的多图表能力，同时承认 Magic 分不开资金。需要更强故障隔离时，建议使用不同 MT5 实例或不同账户；界面只把它作为隔离建议，不宣称能消除市场风险。

### MT5 问题 2：停止时已开持仓怎么办

[推断] **默认不自动平仓。** 停止确认框把「未成交挂单」与「已开持仓」分开：挂单默认撤销以避免停止后新增敞口；持仓默认保留并转人工管理。用户主动选择平仓时，再独立授权并按逐单回执报告结果。Mojo 的已核事实也是停止 Agent 不自动平仓。（`00-FACTS.md §2.2`）

[推断] Netting 中若同品种净头寸混有手工或其他 EA 仓位，禁用「按 Magic 自动平仓本策略」并提示到 MT5 人工处理，不能把整个净头寸当成本策略仓位。

[推断] 必须提示的话术如下：

> 停止后，本策略**不会自动平仓**。你已开的持仓仍留在 MT5 账户，浮动盈亏和保证金占用会继续变化；本策略不再为其加仓、减仓、移动止损或按原规则退出。券商服务器上已存在的止损/止盈（如有）仍按券商规则执行，未设置的不会自动补齐。未成交挂单将按本次选择处理。撤单或平仓结果以逐单回执为准；结果未知时，请先在 MT5 核对。

[推断] 若结果为 `RECONCILING`，文案改为「结果未知，请核对 MT5 持仓与订单」，不得自动重放，也不得显示「已平仓」。停止后不做平台内提现、兑付或资产划转：资金、已实现盈亏和用户选择保留的持仓都留在原 MT5 账户；只有实际平仓后，相关保证金占用才可能释放，界面不得提前写成「资金已返还」。

## B6 · 视觉语言与现有变量对齐

### 色彩结论

- 现有四套 accent 与浅色/深色主题已经正交；继续使用 `[data-accent]` 和 `[data-theme]`，不建立「橙色深色」「蓝色浅色」等组合类。（`src/ui/index.html:9-36`）
- [推断] accent 只负责选择、焦点和主要操作，不承载涨跌、绩效来源或风险等级；浅色小字用 `--brand-deep`，深色用 `--brand-light`，避免直接使用低对比的亮 accent 写小字。
- 涨跌继续用现有 `--up / --down`：浅色 `#E23B2E / #17995B`，深色 `#FF7A66 / #3DDC97`；只用于有正负方向的收益数字，不用于整段资金曲线。
- [推断] **深色资金曲线继续使用 `#7CA9F8` 是合理的**：它与涨红跌绿解耦，在深色面板上保持清晰，也不随四套 accent 改变数据含义。浅色对应使用 `#2563EB`。只新增一个语义变量：

```css
:root{ --chart-equity:#2563EB; }
[data-theme="dark"]{ --chart-equity:#7CA9F8; }
```

- [推断] 回测段用 `--faint` 虚线，模拟段用 `--chart-equity` 点线，实盘段用 `--chart-equity` 实线，发布点用 `--accent`；禁止渐变描边、发光、霓虹阴影和动态背景。

## B7 · 「不放什么」清单

| 不放 | 风险 | 设计替代 |
|---|---|---|
| 1. 「年化 > XX%」「翻倍」「收益榜第一」等营销角标 | [推断] High：把窗口结果包装成收益承诺 | [推断] 展示实际窗口收益、最大回撤、起止日期和记录天数 |
| 2. 「稳赚 / 保本 / 零风险 / 躺赚 / 保守所以回撤可控」 | [推断] High：与历史绩效和风险标签的真实含义不符 | [推断] 明示风险标签来源；固定「历史回撤不是未来损失上限」 |
| 3. 预测收益、未来曲线、AI 估算的缺失绩效 | [推断] High：无法验证且可能被当成实际结果 | [推断] 缺失显示「—」和原因；只画已发生记录 |
| 4. 回测、模拟、实盘混卡、混榜或连续拼接 | [推断] High：把历史演算误读为真实资金结果 | [推断] 页面级单口径；详情三段独立容器与独立指标 |
| 5. 默认 7 天或更短窗口收益榜 | [推断] High：短期偶然性压过回撤与样本长度 | [推断] 默认近 90 天、最大回撤升序；短记录单独分组 |
| 6. 「Top / 官方精选 / 高排名 = 推荐」 | [推断] Medium：排序被理解为平台背书 | [推断] 用户可控排序，固定「排序不等于推荐」，不设 Featured 默认项 |
| 7. 跟随人数、创作者收益额、晒单截图作为一级卡片卖点 | [推断] Medium：社会证明替代策略与风险评估 | [推断] 一级只放同口径结果、回撤、记录天数；作者信息下沉详情 |
| 8. 卡片或星标上的「一键实盘」 | [推断] High：跳过账户、资金、版本和风险确认 | [推断] 收藏无资金动作；实盘必须走完整向导与二次确认 |
| 9. 可点击但无响应的 Run、筛选或充值式按钮 | [推断] Medium：用户误以为命令已经发出 | [推断] 未开放就不放；暂不可用则 disabled 并显示具体原因与修复入口 |
| 10. 缺失资金、保证金或占用数据时按 0 继续 | [推断] High：可能在未知敞口下启动真实交易 | [推断] 阻断启动，显示缺失层与重新同步动作 |
| 11. 「停止 = 平仓 / 停止 = 无风险」，或默认自动清仓 | [推断] High：未授权改变真实敞口，或让用户忽视残留持仓 | [推断] 默认不平仓；挂单与持仓分开确认；逐单回执与人工管理入口 |
| 12. `RECONCILING` 后自动重试或显示成功 | [推断] High：可能重复下单或掩盖未知结果 | [推断] 冻结重放，要求核对 MT5 订单与持仓后再处置 |
| 13. 「非托管，所以平台/EA 碰不到资金」的绝对文案 | [推断] High：混淆资产所在位置与交易授权 | [推断] 写「资金留在你的 MT5 账户；授权 EA 可执行交易，交易可能造成亏损」 |
| 14. 多策略共账户只靠 Magic Number 隔离 | [推断] High：订单归属不等于保证金与净额风险隔离 | [推断] Magic 注册 + Netting 品种互斥 + 组合风险预算；必要时实例/账户隔离 |
| 15. 多策略曲线、基准或体量叠加但没有同口径同窗口 | [推断] Medium：视觉比较制造虚假可比性 | [推断] 卡片只画自身；排行只比较同来源、同窗口完整记录 |
| 16. 花哨渐变、玻璃拟态、Neon、动态背景、收益粒子动画 | [推断] Medium：削弱数据阅读并违背现有视觉约束 | [推断] 平面卡片、现有边框/阴影、静态 SVG 资金曲线 |

## 验收清单

- [推断] 侧边栏只有「策略广场」一个入口；页内两个视图共用筛选与详情，空榜不开放。
- [推断] 默认模拟盘、近 90 天、最大回撤升序；任何收益数字旁都能看到同窗口最大回撤。
- [推断] 任意卡片只含一个绩效口径；回测、模拟与实盘没有共享 path，也没有跨段累计收益。
- [推断] 无数据、无权限、无兼容账户、资金不足、版本不兼容均有具体原因，不存在无响应按钮。
- [推断] 收藏与预览不产生命令；模拟与实盘严格分账；实盘启动、暂停、停止、修改、平仓都有相应确认。
- [推断] 同账户多策略必须经过 Magic 注册、Netting 品种互斥和组合风险校验；停止默认不自动平仓，未知回执不自动重放。
- [推断] 四套 accent × 两套主题都复用现有变量；深色曲线为 `#7CA9F8`，没有渐变、玻璃、Neon 或动态背景。
- [推断] 所有新交互在 `app.js` 用 `addEventListener`/事件委托实现，CSP 下无 inline onclick；示例 SVG 不含虚构绩效 path。
