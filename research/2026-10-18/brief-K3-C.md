## 1. 为什么是 mojo
mojo.trade 的三件事对我们直接有用：
- **Boards**：描述式自建看板（"给我做一个 BTC/ETH/资金费率/隔夜新闻的早间看板"），把关键信息聚合在一个视图。
- **Strategy card + 批准才跑**：请求 → 生成可审阅的策略卡 → 用户确认手数与止损 → 才启动；**每一步都落进记录**。
- **Review**：可追溯信号 / 决策 / 动作的时间线。

以及创始人访谈里的三条工程原则（请务必在设计中落地）：
1. **「谁定什么」边界**：用户定「下多少、什么条件止盈止损」；Agent 负责把自然话写成策略；**可用余额、下单量换算、止损价落地由确定性程序算，模型不参与**。
2. **五层资金账本**：任一层数据缺失就不下单，**绝不用 0 填补**。
3. **停止 Agent 不会自动平掉已开仓位**（用户始终有最终处置权）。

## 2. 你要回答的设计问题

### C1 · DIY 看板组件库（MT5 场景版）
设计一套**牛牛AI 的看板组件清单**（不是抄加密货币那套组件）。要求：
- 组件表：`id / 名称 / 一句话用途 / 数据来源（对应我们已有的 snapshot 字段或需要新增）/ 尺寸（S/M/L）/ 充要条件（缺什么数据就禁用并说明原因）`
- 至少覆盖：账户总览、净值/资金曲线、当前持仓、今日/本周盈亏、自选品种报价、快讯、AI 早间摘要、策略运行状态、风险敞口与回撤、待办/人工核对项、情绪/新闻。（可增删，但要说明理由）
- **第一个组件应该怎么选**（默认 2 个），以及理由（用户第一次打开就有东西看，但不吓人）。
- 拖拽与编辑的交互方案：继续用我们已定的 **Pointer Events + 有序数组 + CSS transform**（编辑态快照 / 取消回滚 / 网格吸附），还是更简单？给结论。
- **空状态与降级**：没连 MT5 / 没数据 / 组件报错时，组件卡片显示什么（必须具体到文案规则）。

### C2 · 「早间看板」自动生成（借用 mojo 的 morning board）
mojo 有「08:00 你的早间看板已经在那里了」这个叙事。请设计我们 MT5 版的**自动晨会**：
- 每天开机/首次连上 MT5 时自动生成什么内容？（持仓隔夜情况、隔夜 swap、昨晚行情、今日财经日历、风险敞口、待人工核对项）
- **AI 参与的部分 vs 确定性程序参与的部分**，按上面「谁定什么」边界逐项划清楚。
- **AI 不可用时**（没连 AI 网关 / 积分不足）看板怎么降级？（遵循牛牛AI 现有原则：**不放点了没反应的东西**，宁可不显示）
- 给出「当天第一次看到的内容」的中文字段级样例（用占位值，不要编真实数字，绩效用「待填充」）。

### C3 · AI 副驾驶：对话 + 执行留痕
现状：我们的 AI 分析还没开放，只有积分/充值；现有的**人工下单链路**是「表单 → 下单前确认票据 → 确认下单 → 回执跟踪（含结果未知的待核对态）」。
请把 mojo 的「策略卡批准 + 全程留痕」映射过来：
- **对话窗口**（用户可以问什么；问出交易意图时怎么转成需要确认的东西）
- **从对话到"确认"的那张卡**（叫什么、展示什么字段、哪些字段必须用户改、哪里写"会自动执行吗"）
- **模型负责什么 / 确定性程序负责什么**（逐条列表）——特别是：报价、保证金、可用余额、最小手数、STOPS_LEVEL 这些**绝不能让模型算**。
- **留痕时间线**：记哪些事件、用什么粒度、能不能导出、与现有 logBox 事件日志的关系（合并？分级？二级抽屉？）
- 明确「AI 不能做的事」清单（至少 6 条）：例如不能在用户没确认时下单、不能修改止损以外的风险参数、不能对结果未知(待核对)的命令自动重试等。

### C4 · Review 与「回所属」查看器
设计审计视图：策略/Agent 做了什么。
- 时间线粒度、事件类型枚举（信号触发、参数变更、下单、回执、拒绝、异常、人工介入）
- **过滤器**（按策略 / 按时间 / 按结果 / 只看异常）
- **严重级别**：INFO / WARN / CRITICAL 三档，各档怎么展示、是否打断用户
- 导出（我们现有 `app:saveLog` 只能导出纯文本日志，是否需要结构化导出？给建议）
- 触发器：**什么事件必须主动通知用户**（联想 mojo 的定时巡查最低 10 分钟一次；我们该多久一次？ETA 考虑 MT5 是本机 EA 轮询）
